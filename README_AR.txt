HANI SOFTWARE — V6 تفعيلات الأدوات المدفوعة وخدمة FRP عبر GSM المصرح
============================================

هذه النسخة توسّع كتالوج V4 بإضافة مجموعة أكبر من تفعيلات وتجديدات الأدوات المدفوعة، وخدمات FRP الرسمية للمالك، مع هوية HANI SOFTWARE وألوان الأسود والذهبي والأحمر.

ما تم في V5:
- 15 قسماً مستقلاً.
- توسيع قسم تفعيل Box & Dongle ليشمل تراخيص وتجديدات أدوات مدفوعة متعددة، مع طلب خاص لأي أداة أخرى غير مدرجة.
- إضافة خدمة إزالة FRP مدفوعة عبر مزود GSM مصرح به، إلى جانب خدمات استعادة حساب Google، مع التحقق من ملكية الجهاز أو التفويض الرسمي.
- أكثر من 130 خدمة/منتج مستقل (كل خدمة لها صفحة تفاصيل منفصلة).
- صفحات الأقسام تتضمن بحثاً وتصفية للخدمات.
- صفحة كل خدمة تعرض الوصف والمتطلبات والمدة والتوفر والسعر الذي يحدده المدير ونموذج الطلب.
- حقول طلب مختلفة بحسب نوع الخدمة: IMEI/SN، الطراز، Player ID، المنطقة، فئة البطاقة، حساب المزود، مدة التأجير وغيرها.
- كتالوج الألعاب وبطاقات الهدايا والاشتراكات وتراخيص الأدوات وتأجير الأدوات وخدمات الملفات.
- الأسعار الفعلية غير مدخلة؛ جميعها يحددها مدير HANI SOFTWARE بالدولار أو الجنيه.
- صفحات منفصلة وروابط رجوع مع تصميم متجاوب.

مهم حول مطابقة المرجع:
تمت مراجعة أقسام الموقع المرجعي التي أمكن الوصول إليها: IMEI Services وServer Services وTools Rental، مع ظهور فئات الألعاب وبطاقات الهدايا والتفعيلات والاشتراكات. صفحة File Services لم تكن متاحة أثناء المراجعة؛ لذلك أُضيفت خدمات ملفات شائعة كقائمة أولية تحتاج مطابقة نهائية مع قائمة مزودك.
هذه ليست نسخة حرفية من Express Unlocker، ولا تنسخ شعاره أو أكواده أو صوره أو نصوصه الخاصة. تفعيلات الأدوات المعروضة هي طلبات تراخيص وتجديدات رسمية فقط، ويجب تأكيد التوفر عبر موزع معتمد. يتضمن قسم FRP خدمة مدفوعة عبر مزود GSM مصرح به، ويظل قبول كل طلب مشروطاً بتوافق الطراز والنظام لدى المزود والتحقق من ملكية الجهاز أو التفويض. لا تُقبل الأجهزة مجهولة المصدر أو المبلغ عنها مسروقة.

النشر على GitHub Pages:
1. فك ضغط HANI_SOFTWARE_V5.zip.
2. ارفع محتويات المجلد نفسها إلى جذر المستودع بحيث يظهر index.html وassets/ في الصفحة الرئيسية.
3. اضغط Commit changes.
4. من Settings > Pages اختر Deploy from a branch ثم main و /(root).
5. انتظر اكتمال النشر ثم افتح رابط الموقع.

حالة Supabase:
هذه النسخة واجهة أمامية للمعاينة وليست متصلة فعلياً بقاعدة البيانات. النماذج لا تحفظ طلبات حقيقية، ولا يوجد خصم محفظة أو إدارة مالية حقيقية حتى الآن.
قبل استقبال العملاء أو الأموال يجب إعداد Supabase Auth وRLS وصلاحيات المدير على الخادم، وإنشاء دالة آمنة تنفذ إنشاء الطلب والخصم وسجل الحركة في معاملة واحدة، مع حفظ سعر الصرف المستخدم لكل طلب. لا تضع service_role key في ملفات JavaScript العامة.


تحديث V6: تمت إضافة منتج مستقل باسم «إزالة FRP عبر خدمة GSM مصرح بها» داخل قسم FRP. تظهر الخدمة في الكتالوج كطلب مدفوع منفصل، ويُطلب IMEI/SN والطراز وإثبات الملكية أو التفويض، وتُحدد قابلية التنفيذ بعد فحص التوافق لدى مزود GSM.

تحديث V7 — لوحة إضافة خدمات المدير:
- إضافة خدمتين مستقلتين داخل قسم FRP: FRP HONOR KY وFRP SAMSUNG.
- لكل خدمة صفحة تفاصيل منفصلة، مع حقول IMEI/SN والطراز وإصدار النظام وإثبات الملكية أو التفويض.
- إضافة نموذج في admin.html يسمح بإضافة خدمة جديدة لأي قسم، وتحديد الاسم والوصف والتفاصيل والمتطلبات ومدة التنفيذ والتوفر والسعر والعملة، ووضع HOT.
- يمكن تعديل الخدمات التي أضافها المدير أو حذفها من نفس لوحة الإدارة.
- افتح admin.html مباشرة للوصول إلى إدارة الخدمات.
- تنبيه تقني مهم: التخزين الحالي localStorage تجريبي ومحلي على نفس المتصفح والجهاز فقط، وليس نظام إدارة آمن متعدد المستخدمين. لا تعتمد عليه للإنتاج أو لإدارة أسعار وطلبات حقيقية. يلزم ربط Supabase Auth وPostgres وRLS بسياسات تمنح التعديل لحساب المدير فقط، ثم نقل الخدمات إلى جدول services.
